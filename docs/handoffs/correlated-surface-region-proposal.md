## Exact gap and hypothesis

`source_surface_envelopes._plane_box` constructs eight correlated ray/height
vertices. `_clip_support` already intersects that convex region with a declared
finite support. `_bounds_envelope` then retains only coordinate-wise minima and
maxima. Its documented warning is correct: a point in the enclosing box need
not satisfy the original pixel/height constraints.

`SurfaceIntervalObjective.evaluate` in
`source_surface_interval_construction.py` in its default mode computes
`world - np.clip(world, lo, hi)`. Consequently every point inside the enclosing
box receives zero surface loss, including geometrically incompatible points.
The existing fitter can therefore satisfy this surrogate without satisfying
the supplied conditional image/support region.

A purely analytical witness: camera origin `(0,0,2)`, rays `(u,v,-1)`,
`u in [1,2]`, `v in [0,1]`, height `z in [0,1]`. The outer box is
`[1,4] x [0,2] x [0,1]`. Point `(1,0,0)` lies inside that box but projects to
`u=0.5`, outside the supplied pixel range. Its nearest admissible point is
`(1.5,0,0.5)`: old loss is zero; exact half-squared distance is `0.25`.
This is a geometry witness, not a measured exercise sample.

Hypothesis: using the actual convex region removes these false zero-loss
solutions while retaining complete observations, original bounds and ambiguity.
There is no additional image/model inference or new physical assumption.

**This is not demonstrated false world admission.** The existing fitter's
final `source_endpoint_image_nonregression` gate checks every positive-weight
source endpoint against its original error; floor, depth and camera-domain
gates also remain independent. Those gates can reject a trial despite its zero
box loss. They do not test absolute membership in the separately supplied
pixel/height region. In the existing explicit `qualified_surfaces` mode, a
reference can also lack positive-weight image endpoints. No saved admitted
world is claimed to exhibit this counterexample.

## Opt-in contract

Add optional `constraint_geometry: "correlated_pinhole_region_v1"` to the
existing `source-surface-fit-config-v1` JSON used by
`body-reference-propose --surface-config`. Omission retains exact old behavior
and payloads. No new command, product, body profile or control route.

The optional key survives config parsing, the frozen descriptor and snapshot
equality. Reject unknown values; never infer the mode from camera or surface
content. A manual config without this key retains its exact prior descriptor,
serialized envelope, numerical objective and source-selection behavior.

- `prepare_source_surface_envelopes` accepts the corresponding optional keyword.
  In this mode only, retain a bounded convex-region descriptor alongside the
  existing outer box in `world_envelope_m`. Keep the original outer box for
  comparison and all existing source/annotation/camera/support bindings.
- Support the existing undistorted pinhole branch (`radial_k1 == 0`) first.
  Nonzero distortion is explicitly unavailable in the new mode, not silently
  converted to an exact region or sent through the old box loss. Default radial
  behavior remains unchanged.
- Preserve the closed convex region from four pixel-ray planes, two height
  planes and, where applicable, four supplied finite-support planes. Retain
  boundary, planar, line and point cases. Empty, ill-conditioned or numerically
  uncertifiable cases are unavailable, never zero loss or a chosen midpoint.
- `prepare_surface_interval_objective` consumes the trusted prepared region
  under the same exact body/source/entity/frame/clock joins. Each query computes
  closest-point residual to that region, not to its enclosing box. Cache the
  region once; no repeated source parsing, geometry reconstruction or I/O.
- Reuse the already archived `constrained_qp.solve_feasible_qp`, unchanged:
  three variables, identity Hessian, gradient `-world`, at most ten linear
  planes and a feasible seed from the retained region vertices. Restrict each
  solve to 32 iterations and at most 0.05 seconds within the existing shared
  0.25-second query deadline. No new solver, dependency or installation.
- Store exact rational plane coefficients from the current rational ray
  construction, not a hull fitted to rounded extrema. Region record:
  `profile: "source-surface-correlated-region-v1"`, `unit: "m"`,
  `convention: "A*x >= b"`, `halfspaces_q` (at most ten four-coefficient rows),
  `affine_hull_q` (at most three four-coefficient equalities), and
  `feasible_seed_q` (three coefficients, a solver-only feasibility witness,
  not a selected reconstructed target). A rational coefficient is the
  reduced `[numerator, positive_denominator]` pair serialized as decimal strings.
  Cap the complete record at 8 KiB. Normalize each plane before binary64 query
  arithmetic and retain the solver's original primal/KKT tolerance and status;
  do not describe floating projection as exact arithmetic or measured accuracy.
- Failed/limited/uncertifiable query projections remain unavailable and prevent
  fit acceptance. The consumer refuses to convert them to zero cost; its
  nonregression gate also rejects them. Preparation-time unsupported inputs
  remain explicitly unavailable. Closed planar/line/point cases are tested.
- The squared-distance gradient is `J.T @ (world - closest_point)`; use the
  independent active/equality-normal projector for the piecewise residual Jacobian and
  existing Gauss–Newton interface. Retain active-set/numerical status; check
  gradients both away from and at a full-dimensional face transition. The
  squared-distance gradient is continuous there; the projection Jacobian can
  change. Permanent affine-hull normals still apply on lower-dimensional regions.
- The existing fitter consumes the same residual/gradient contract. All task,
  source-image, floor, depth, body and final admission gates stay unchanged.
  The new objective is an explicit construction option, not a scorer change.
- The new geometry and its input identity must survive the existing source-slot
  and before/after audit. Keep current 8 MiB prepared-cache, 128 KiB row and
  4 MiB fitter-audit limits; reject complete oversized output rather than trim.

This still requires supplied camera, height interval, pixel ranges, body/world
mapping and a justified static-support assumption. It removes no such human
input and does not infer contact from overlap. Its gain is a faithful numerical
constraint, not evidence that those supplied assumptions are physically true.
