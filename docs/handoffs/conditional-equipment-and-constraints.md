## Source-pinned perception bridge

`exercise-perceive` connects saved server-key OpenAI analysis to the existing
local body and canonical Meta tracking adapters. It reconstructs the exact
provider request from saved sampled images, verifies request/response/receipt and
the current prompt/schema/model, then checks **every sampled image and decoder
timestamp** against the original MP4 in one bounded decode. Source FPS metadata
is checked separately; nominal times do not replace native body timing.

The AI proposes first-image nonhuman equipment regions only. A sealed local body
supplies a separate tracking-only person anchor from construction-partition frame
zero landmarks. Confidence, source/image/manifest pins and explicit 5% padding
remain inspectable. This is not a rigid person box or proof of identity. The
route permits at most three equipment regions plus this anchor; it never silently
truncates a larger inventory. Unusable, clipped or occluded initial poses abstain.

```sh
# Offline: validate the saved analysis and prepare the exact tracking request.
.venv-lab/bin/python -m weft exercise-perceive \
  --video ORIGINAL.mp4 --analysis SAVED_PORTAL_ANALYSIS \
  --body-source EXACT_SEALED_BODY --out NEW_DIRECTORY
```

Without `--body-source`, offline output is explicitly equipment-only preparation
requiring a body anchor before assembly or paid tracking. For exact existing
tracking use `--saved-tracking`; every initialization must match both the AI
regions and the independently derived body anchor. The resulting sealed base /
equipment packages still must pass ordinary role, geometry and lab admission.
`evidence_ready` is not `simulation_ready`.

Explicit `--execute-tracking --meta-budget AMOUNT` uses the canonical shared Meta
ledger; local body/anchor gates run first. Original MP4 only, ≤37 MB /500 frames;
no automatic conversion. One request, no retries. The absolute work deadline is
rechecked after payload/key setup and after reservation, immediately before send;
expiry retains an already-created unknown reservation with `request_count: 0`.
Optional deadline/FPS arguments preserve legacy callers' metadata/default behavior.
Local preparation has cooperative checks; the existing network subprocess has
the hard request timeout. This is not an OS wall-time limit on all local work.
