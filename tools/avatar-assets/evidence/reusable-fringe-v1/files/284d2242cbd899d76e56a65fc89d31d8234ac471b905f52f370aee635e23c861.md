# Portable fringe integration review

Read-only design review. No native job, provider call, model derivative, production edit, appearance approval or profile promotion was performed. The production adapter and helper tests were still being implemented during this review.

## Smallest reliable adapter

1. Run after source transforms, material/normal repairs, part assignment and final weights. Use actual loop-triangle corner UVs/normals; do not use `texture_colors()`'s first-loop nearest per-vertex approximation for RGB. Points, normal vectors, regional flow and fixed design views must share the applied, meter-scale Blender mesh frame.
2. Construct positive furry-face eligibility from the user mask and selected material names. Exclude explicit non-fur surfaces, final moving-part ownership, color-corrected vertices and authored closure materials. Resolve original material aliases through undercoat reports; do not classify every UV1 material as a closure. Unknown exclusion names should fail, not silently do nothing.
3. Call the allocator with exact source indices, triangle-corner attributes and a recorded bone-name-to-slot map. Copy endpoint weights to their matching tips. Reject unsupported skin ambiguity or more than four nonzero deform influences rather than silently changing the source skin. Nondeforming mask vertex groups are not joints. Use the helper's original plus reversed triangles and its source-surface normals; the material stays single-sided.
4. Validate each selected material's exact source image/UV contract separately. The new color helper accepts distinct textures; the legacy full finisher/native groom still assumes one shared image. Do not claim that the component removes that separate limitation.
5. For Blender-loaded sRGB byte images, image.pixels contains encoded RGB in bottom-up rows. Convert boundedly to top-down uint8 and pass source UV as `(u, 1-v_blender)` to the atlas sampler. Keep raw REPEAT coordinates, including negative values. Convert returned top-down/glTF-V-down atlas UV to `(u, 1-v)` exactly once when assigning Blender UVs; glTF export performs its normal UV convention conversion. Save a top-down PNG and load it as sRGB. Do not multiply the baked RGB by legacy COLOR_0 again; do not inherit the source tangent-normal texture onto fins.
6. Decode/retain unique source images only, with the combined 16 MP limit. Avoid concurrent whole-source float RGBA, uint8 RGBA and full linear-RGB copies. Release temporary source pixels before native grooming. A 4096² Blender float RGBA read alone is 256 MiB.
7. The atlas helper returns four UVs per fin even though reversed triangles double the face count. Preserve this vertex order and map every Blender loop from its vertex. Emit an explicit MASK material, cutoff 0.18, single-sided, metallic 0 and the intended roughness. Validate final exports instead of assuming Blender retained custom normals, alpha mode or weights.
8. Reserve `base export vertices + 12*max_fins + 4096 <= 100000`, and `base triangles + 4*max_fins <= 100000`. Do not use the old six-corner budget. Pin allocator, atlas, adapter and host validation sources in finishing snapshots, native reuse and unfinished-pipeline source binding. Keep sealed historical deliveries resumable by their existing rules.

## Integration pitfalls to close

- The allocator initially rejected source UV outside 0..1, but the existing fox uses valid REPEAT UVs from -0.153 to 1.007. The helper owner fixed this before freezing source SHA `24eb6347abccae2a885758aa3f8e49e92dcca26695c2bc55aaf220963c7870b9`: bounded finite raw coordinates are retained, without per-endpoint modulo. Its owner reports 15 passing focused tests, including preserved integer-wrap UV seams; this review did not rerun them.
- `shared_color_texture(all materials)` rejects the fox's distinct textures and constant accessory materials. Per-selected-material contracts fix the component only; they do not establish full heterogeneous native grooming.
- `quality_policy.py`, `AUTHOR_FIELDS`, mixed-coat masks and non-fibrous rejection must understand the explicit alternative. Native groom and regional flow remain required for the full finishing profile. No automatic default/Muse promotion follows.
- The main exporter hides all portable coat objects before the native portrait. That is appropriate when showing a distinct native groom, but a component review must render the actual fringe representation separately; the native hair image cannot prove portable quality.
- Motion camera margins must include fringe length. Preserve all requested action names, timing and exact source attachments; a rest-only picture cannot prove moving root attachment.
