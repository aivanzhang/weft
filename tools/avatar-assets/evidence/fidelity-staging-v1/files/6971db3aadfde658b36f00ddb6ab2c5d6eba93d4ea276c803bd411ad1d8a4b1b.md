# Native float-vector normal control

**Passed as a small normal-storage/export component test. No avatar quality acceptance or production change.**

Six exact worst panda/fox triangles were tested with three storage methods (18 triangles total). All six legacy `CORNER INT16_2D` controls reproduced the original failure. Both `POINT FLOAT_VECTOR` and `CORNER FLOAT_VECTOR` retained intended native normals exactly; exported error stayed below the unchanged 0.0002 component gate.

| Storage | Maximum native error | Maximum exported error | Exported failures |
|---|---:|---:|---:|

| Point float-vector | 0 | 0.0000344962 | 0 |
| Corner float-vector | 0 | 0.0000344962 | 0 |

The test also checked unique position correspondence, oriented triangles, native before/after-export equality and standard GLB normal validity. It preserved editable `source.blend`, actual exported `model.glb`, all native values, source pins and exact commands. The input custom normals were written with `mesh.attributes.new(name='custom_normal', type='FLOAT_VECTOR', domain='POINT' or 'CORNER')`, not the legacy setter.

Independent CPU verification: **0.263 s**, sampled memory **unknown/null**; PID 37741 exited before sampling. Bounds were 60 s / 1 GiB / 64 MiB / four threads.
