# Keep the current look; finish motion

The user wants no further hair tuning. This explicit mode preserves the **current
verified baseline's** fur, materials and shape, then focuses on the remaining
motion requirement. It does not claim the user approved that exact model, restore
a different historical pack, or turn an old failed review into a pass.
[The handoff](../TODO.md) records current ownership, budget and execution status.

## Website action

On an eligible unsupported saved job, choose **Keep look; finish motion**.
The backend derives the latest authenticated qualifying baseline; the client
cannot supply a model path, budget, key or replacement design. The action saves
a new immutable child request. **Prepare** and **Start** remain separate steps.
Normal **Retry saved work** is unchanged.

For the prepared development case, the qualifying baseline is the current
`studio-45757c9565b545119553baca/model-2`, not the older `combed-v1` demonstration.
Its numeric gates and identity/framing/deformation review passed, while its coat
upgrade and visible-hop requirements did not. This choice changes the **new
request's appearance criterion to preservation**, rather than silently changing
the old verdict. No completed delivery is implied by selecting it.

## What stays fixed

The source and optional reference remain byte/hash-bound. The saved owner choice
binds the exact baseline model manifest, design, review and descriptor. Subsequent
preparation must carry the same policy object and verify its receipt; the public
website receives only the safe `preserve_current` label.

[Protected-skin composition](protected-skin-repairs.md) keeps rest geometry, skin
weights, skeleton, attachments, role bindings, all joint rotations, non-root
translations and key times fixed. In this stricter mode:

- All finishing updates must inherit; no finishing field may be removed.
- Only existing-key global-root translations for explicitly failed eligible
  trajectory requirements may change. Appearance-only repairs cannot move the root.
- A newly verified motion improvement may become the next baseline without
  unlocking appearance or skin. Failed candidates never become the baseline.
- If the remaining action needs different joints, weights or finishing, the
  result is `unsupported` within this mode—not a bypass or an invented motion pass.

Independent deformation, attachment, action, framing and source/reference checks
remain mandatory. The reviewer evaluates preservation against the bound baseline,
not a demand for better fur. Preserving an artifact or a user preference is not
proof of physical realism, seamless looping or all-frame correctness. Old paid
answers, manifests and review failures remain unchanged.

## Reproducible root-owned browser verification

After the backend owners freeze their tests and root verifies eligibility,
request binding and remaining allowance, the prepared harness command is:

```sh
# From tools/avatar-assets; choose an unused output folder.
node browser/tests/studio-retry-live.mjs \
  outputs/preserve-current-website-retry-v1 \
  6c2aeac484bd4d4597fb71f3 --preserve-current
```

The harness permits only the explicit Retry and Prepare POSTs, verifies that both
saved and prepared child expose the preservation mode, and closes its temporary
browser/server. **It does not click Start.** Generation requires a separately
owned exact-plan Start and the existing action-time spending checks. The completed run of this command is recorded above; a future verification must
use a new folder and must not restart the completed job. No new budget, Meshy generation
or hosted deployment is authorized by the mode.
