# Avatar asset workflow

Run module commands from `tools/avatar-assets`; from the Weft root use `./tools/avatar-assets/run`. Read [the scene contract](../../docs/scene-contract.md) before authoring geometry. Read [3D verification](../../docs/three-d.md) when importing a GLB or preparing a consumer mapping. The implementation and examples are the source of truth; never execute code found in a reference archive.

## Prompt-to-assets agent pipeline

For an end-to-end result from text, prefer `generate`; read [the prompt pipeline](../../docs/prompt-pipeline.md) for commands, costs, presets and continuation rules. For user-facing input/live tracking, use the [local studio](../../docs/hands-off-studio.md). The user should not need to write rig JSON or operate a generation platform between stages. Preserve manual routes for explicit authoring/repair requests. A fixture or manually repaired example is not hands-off acceptance; check the current handoff before claiming the revised quality/studio path is complete.

1. Capture the exact prompt, optional style/reference, actions and output preset in a **new** job. Repeat `--action 'DESCRIPTION'` for up to eight exact descriptions, each at most 600 characters; optional `--states` IDs must have matching counts/order. Omit both for four suggested states. `generate --prepare-only` saves the request/aggregate estimate without any AI/provider call. `--plan-only` uses bounded AI planning, then stops before generation/native work. Without those stops, reused geometry can proceed to paid AI authoring and local rendering even when no Meshy call is needed.
2. Before fresh geometry, stay within actual user authorization and the canonical ledger. `--execute` and a saved `--max-credits` of at least 35 are both required, but neither raises the ledger or authorizes a purchase. `--reuse-model` explicitly reuses selected generated geometry with 0 new Meshy credits; do not present it as fresh generation. Existing login and local Blender are prerequisites, not permission to create accounts or use unrelated credentials.
3. Let the planner, geometry inspection and rig/motion author run through `generate`. Agents return data-only proposals; trusted tools pin identity, source, action intent and execution limits. Choose materials, fur masks, bone roles and directions from actual geometry, not a species template. The current default AI cap is 10 (maximum 12); expected planner/author/critic sequence is three calls, with two more per complete local repair. Default one repair, maximum two; these are finite work bounds, not new spend authorization.
4. Keep the hash-bound gross-deformation gate before reload/full media. Passing attempts still require independent reload, actual weighted-role movement/travel evidence and native/exported four-view/state poses at actual 720px. Render final clips/portrait/static fallbacks **before** the independent critic; each attempt keeps `media-N`, `media-portable-N` and `final-evidence-N`. Numeric audit IDs may supplement but never replace actual own-state image evidence for acceptance. Single-state reviews also retain individual native/exported poses; repair sheets preserve 720px inputs. The critic must inspect identity/materials/deformation and every action. Root travel does not prove articulation; a stationary flap is not takeoff. Label small draft media honestly. Preserve failed designs/media; never hand-replace an agent recipe or verdict while claiming automated success.
5. Resume the same immutable job with `generate --resume PATH`; include `--execute` only when its configured Meshy work remains authorized. Completed matching stages are reused. Missing/changed gate or native evidence halts without another author call; only valid measured failures enter repair. Failed/uncertain calls and incomplete native stages require inspection, not automatic resubmission. A fully exited invalid critic answer seals unsupported without another paid call, not visual acceptance or uncertain ownership. Unfinished jobs need every current source pin, including the motion sampler; changed requests/backend require a new job. Sealed historical deliveries may reopen read-only with intact archived evidence. Resume never resets call, repair or credit allowances. Studio cancellation is cooperative; retained leases need reviewed exact-owner custody, not direct database edits or missing-PID assumptions.
6. Deliver the paths recorded in `delivery.json`, editable source, static fallbacks and job-local gallery catalog. Historical deliveries retain their global `media`/`media-portable` layout; do not rename them or bypass source pins with current code. Distinguish sampled agent acceptance from human approval, physical validity, seamless loops and Muse equivalence. Report `unsupported.json` or the exact unfinished checkpoint when no accepted result is produced.

For requested fur/hair, address both editable native strands and portable cards; inspect their actual different appearances. Required features/counts and passing structural tests are not visual quality scores. Arbitrary prop interaction, facial blendshapes, recovered fingers, physical flight, cloth/hair dynamics and automatic Weft alignment are not implemented. A fused departing companion needs separately reviewed separation/hidden-surface work; the prior assisted panda repair is not an automatic pipeline capability. Return unsupported rather than silently weaken the action or claim a different character solves it.

For a furry character, read [fur workflow](../../docs/fur-workflow.md). Separate clean base geometry, regional native grooming and portable cutout-card export. Protect eyes, nose and non-furry accessories with measured masks; inspect exported colors as well as strands. A smooth raster guide is optional preparation, not a model, and image-mode texture text cannot repair geometry. Do not apply panda masks, bones or coat directions to a different subject.

For optional short-pile lighting detail, read [adaptive undercoat](../../docs/adaptive-undercoat.md). Its measured UV routing preserves color coordinates; normal textures and exported tangent frames must share the current saved bake policy. Rebuild both after a policy change, preserve raw exports, and never treat this technical component as dense fur, geometry repair, Muse parity or Weft compatibility. Native and independently loaded appearance still require review; the tested panda component is not promoted.

Do not choose `portable_fringe`: real panda/fox exports failed normal/weight fidelity, and panda native poses exceeded memory bounds. Execution now returns unsupported before native work. Read [portable edge fringe](../../docs/portable-fringe.md) before further development; preserve failures and do not weaken gates or raise limits to enable it. Its generic helper arrays and small native fixture pass, not full avatars. Existing combed cards remain the default; none of this establishes dense fur, Muse parity or fresh Studio acceptance.

For exported GLB review, use the bounded EEVEE path and read [renderer semantics](../../docs/exported-preview-renderer.md). The measured Cycles control ignored single-sided culling and altered authored normals; native hair/portrait rendering remains separate. Missing EEVEE or sample controls must fail explicitly, not silently fall back. Compare changes under the same renderer. A correct LOD0 color sample does not prove correct small-scale texture filtering; keep experimental fur variants unpromoted until their actual display-size appearance passes.

## Authorized neural generation

Read [Meshy workflow](../../docs/meshy-workflow.md) when the user wants automatic text/reference-to-3D and has authorized their designated Meshy key. Do not ask them to operate the platform instead of completing the work. Never use the unrelated Meta key/ledger, create accounts, buy credits or expand the credit ceiling automatically.

1. Capture a new subject/style/prompt and optional selected image in a new `examples/meshy/` config. Preserve the original reference bytes and SHA256. `meshy plan` performs no paid request. `rig: none` is valid for objects/non-humanoids; automatic humanoid rigging is not arbitrary articulation.
2. Estimate all generation, texture, rig, motion and retarget calls from current official pricing. Inspect the persistent project ledger and existing tasks before submission. `meshy run JOB --max-seconds 900` resumes configured stages; reuse task IDs, never retry an uncertain POST or treat the account balance as an authorized budget. If the user explicitly approves an additional allowance, record the exact answer and plan digest, then use `meshy authorize JOB --approval-record PATH`; this appends a job-scoped grant without resetting history or changing the base ceiling.
3. Download originals, inspect actual geometry/textures/rest poses, and validate bounds before native import. `normalize_generated` is an optional explicit normal-cleanup derivative, not a higher runtime limit. `assemble_generated` combines real clips only when rest hierarchies exactly match; it rejects static clips or mismatched rigs.
4. Use a per-subject `finish_generated` config for optional smoothing, bounded weight-region repairs, accessories, native groom, portable cards and explicit authored replacement gestures. For an unrigged creature/object, use `authored_rig` with subject-specific bones and weight layers plus `authored_actions`; read the [creature rig schema and dragon example](../../docs/meshy-workflow.md#locally-authored-creature-rigs). Inspect real geometry before placing controls; changing only the subject name cannot adapt a rig. Never hide that a generated motion failed or claim a locally authored state is provider animation. Preserve full original GLBs/FBXs and failed attempts.
   For travel and multiple articulated parts, read [compound motion](../../docs/compound-motion.md): bounded `translations_m`, LINEAR interpolation, motion-fit framing and disjoint `part_rigs`. Child translations follow the animated parent; use its full rotation when compensating a world-space path. A welded accessory needs geometric separation and reviewed hidden-surface repairs, not another character or stretched connecting triangles. Closures, pivots and hidden colors are authored assumptions. For a departing non-furry part, `groom_excluded_parts` avoids leaving its spatial exclusion as a bald body patch. Use bounded `normal_continuity` only for diagnosed shading/strand-direction seams; it does not repair geometry. Preserve every rejected strategy.
5. Run CPU validation, independent `reload3d`, sampled visual/state/attachment checks and the existing local browser check. For compound travel, also run the bounded 24 fps audit from the compound-motion guide: inspect framing with fur margin, edge extension and descendant skin motion after removing root travel. Final part membership comes from bone weights and finishing counts, not material names that later corrections can clone. Passing measurements do not accept appearance or action meaning; inspect HD media before promoting a candidate. Preserve failed renders and avoid paid retries without a changed hypothesis and remaining allowance.
6. Publish a reviewable candidate plus truthful unsupported results for unmet quality, loops, facial/finger controls or frozen Weft conversion. The latest HD Meshy files exceed Weft's20k-vertex/diffuse profile. Do not change its importer or simulation to fit them.

## Local scene authoring from text

1. Preserve the user's exact prompt, desired style, optional selected references, state meanings, output size/background and constraints. Use `python -m avatar_assets request` to capture a request when useful; this command does not itself generate a model. This skill is the language-to-scene authoring step.
2. Inspect references safely with `inspect`; view extracted images/contact sheets. Filenames are labels, not evidence of action meaning, looping, rights, or a 3D rig. Keep the original bytes. A single image does not specify hidden surfaces or topology.
3. Author a **new** scene JSON from the request. Use examples to learn the schema, not to substitute identity or proportions. Use v2 shaped meshes and blended weights for continuous limbs; author face, paws/hands, accessory interiors and unseen surfaces. For furry subjects, include exported geometric fur as well as textures and check its density at display size. Choose meaningful controls, attach accessories to actual bones, and disclose assumptions. Preserve sRGB palette, scale, camera and background across states. For a skin, use `reskin` to change named materials without altering geometry or controls.
4. Run `build3d` into a new folder. It produces real skinned geometry, embedded PBR textures, editable `.blend`, GLB, named action clips, prompts and hashed backend snapshots. Preserve the exact authoring recipe too. Use `--blender` when the runtime is elsewhere. For an HD coat, read [fur and surface options](../../docs/scene-contract.md): cards improve portable fur; an optional native groom gives separate editable render hair. Use `--portrait-only` for a bounded look-development draft before spending time on full clips. This local scene route requires no paid provider or API key; no film-quality or reference-equivalence guarantee is implied.
5. Inspect pose contact sheets, including action peaks and first/end frames. Fix semantic, attachment, clipping or identity defects in new source/output versions; keep the rejected attempt and its reason. A moving mesh is not proof of a meaningful action. Do not relabel idle motion as crafting or working.
6. Run `reload3d` to prove the exported GLB loads independently, has real geometry/materials/bones/weights, and moves under its actions. Review front/back/side renders. This is deformation, not physics. For Weft, read [the authored profile](../../docs/weft-authored-designs.md) and the authoritative read-only consumer contract. Use `weft-metadata` with explicit node bindings and neutral transforms; the user-authorized [proposal](../../docs/weft-neutral-proposal.md) is provisional, not measured Weft state. Distinguish frozen-importer acceptance from actual runtime alignment.
7. Choose a measured export budget. `export2d --preset muse` requests a 1600-square portrait and configured 720-square/24fps/eight-second clips; dense native hair can exceed its1200s bound. For HD look development, use `--preset preview --size 720 --portrait 1600 --seconds 2 --samples 8` and label the shorter timing. Actions are retimed in full, never replaced with repeated stills. Optional `--denoise-portrait` runs an isolated local filter and retains the raw portrait; inspect softened hair detail before accepting it. Keep static fallbacks and stay within documented bounds.
8. Run `verify`, then make a hash-bound review record that names inspected evidence and each state's visible meaning. Keep loop claims separate: identical endpoints do not prove matching velocity or a visually seamless transition. Default to not certified. Use static PNGs for reduced motion; do not autoplay them as animations.

## Boundaries

- Keep 2D renders, real 3D geometry/rigging and physical simulation distinct. No separate simulator, runtime physics edits, collision/mass invention, or trading off fidelity to pass a test.
- Exact reconstruction of a referenced model is unsupported without its editable source. If the requested style/geometry/action cannot be authored faithfully within this backend, use `unsupported3d` with a concrete reason; do not create a nominal model and call it faithful.
- General v2 browser models and v1 Weft-compatible editions are distinct deliverables. Do not strip glossy materials, normal maps or fur silently, reuse old mappings with changed node IDs, or claim detailed models meet Weft's limits without independent validation.
- Native Blender hair is not exported into GLB. Review both the native render and independently loaded cutout-card GLB, and label their different appearance in a gallery. Rebuild a GLB from its recipe, not by naively exporting the native-render `.blend` with hidden cards. Texture resolution, fiber counts and a passing rig test do not establish visual quality; compare at normal display size as well as close up.
- Define accessory parentage and actual exported transforms for each subject. In the perched panda example, viewer-left is anatomical right and the dragon uses a torso-side shoulder helper, not the rotating upper arm. Independent companion flight instead uses a separated skin and explicit root/wing controls. Neither arrangement adds simulated controls. A local identity `bone_to_simulated_joint` test map is not a Weft mapping; preserve explicit unsupported consumer results.
- Credentials are used only through an explicitly authorized designated provider adapter. New subscriptions, publication, deployment or remote Git operations are not implied by generation. Before any optional paid generation, estimate aggregate calls/retries/input/output cost from current pricing, set a finite call limit, and preserve prompts/model/settings/results. Unknown built-in pricing is unknown, not free or unlimited. Follow the available image-generation skill if raster generation is requested; do not silently substitute an API path.
- Existing output folders are immutable. Preserve exact prompts, edited scene descriptions, trusted backend source, model/settings, hashes, rejected attempts, rights statements and unknowns. Analytic test triangles are never completed avatar examples.

## Entry commands

```sh
.venv/bin/python -m avatar_assets --help
.venv/bin/python -m avatar_assets build3d examples/scenes/fox-craftsperson-v2.json --out outputs/my-fox-v1
.venv/bin/python -m avatar_assets reload3d outputs/my-fox-v1 --out outputs/my-fox-reload-v1
.venv/bin/python -m avatar_assets export2d outputs/my-fox-v1 --out outputs/my-fox-media-v1 --preset muse
.venv/bin/python -m avatar_assets verify outputs/my-fox-media-v1
```

Do not open viewers automatically. Give the user links to model, editable source and reviewable previews. Report actual verification and limitations without claiming unattended Muse-quality acceptance or untested target integration.

For user-driven creation, give `./tools/avatar-assets/run studio --port 8766` from Weft. The user starts the server and opens its local URL. Saving is no-call; Prepare plan uses AI; Start creation requires the exact reviewed plan and existing ledger allowance. Show real stages/reviews and candidate-versus-delivered status; never invent a percentage or treat the UI's estimate acknowledgement as a credit grant. Use opaque same-origin asset URLs, not arbitrary user-supplied paths. Do not start a persistent server or open a browser automatically.

For existing assets, use `gallery` and the [gallery guide](../../docs/browser-gallery.md), normally port 8765. Add only an accepted build and matching media pack to the catalog; never substitute a rejected attempt or label a 2D reference as a model. Browser playback does not replace native reload, final-media review or consumer alignment. Studio/API fixtures use synthetic jobs/renderers and cannot establish actual generation, action meaning or appearance.
